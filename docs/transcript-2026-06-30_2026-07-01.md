### Exchange 8 — Docker, access, webhooks, local dev

**User:**

> Porque se usa docker para instalar tudo separado? Qual a vantagem? Mesmo separados eles falam entre si? Django e boto são pur python? E redis, celery? Porque precisamos dele? Eles tem ui ou são só algo que fica instalado e invisível? Se pai estar tudo em uma vm, como eu acesso a vm e "abro o python"? Django app fica rodando 24/7? Qual dessas peças é responsável por ficar monitorando o que chega da kindness, ls, Kobo via api e webhooks? O Django precisa de algum software pra rodar ou ele em si é o app sozinho? Se fosse na minha máquina local ao invés de vm , consigo instalar o Django app como se fosse um app qualquer? se for ter uma forma de o admin logar no orchestrator na para ver task status, por ex, é via browser? O servidor que " hospeda " o Django app no qual vou logar éa própria vm?

**Assistant:**

- **Docker:** isolation, reproducibility, easier install; containers talk via internal network
- **Django + boto3:** Python libraries; Postgres/Redis are separate programs
- **Redis + Celery:** background jobs; no UI by default (optional Flower)
- **Access:** SSH for terminal; browser for Admin/API; not an interactive Python REPL in production
- **24/7:** Gunicorn, Postgres, Redis, Celery worker, Celery beat
- **Monitoring integrations:** Django receives HTTP (Kindness, Label Studio webhooks); Celery beat polls Kobo API
- **Django needs:** Python + Gunicorn + Nginx/Caddy + Postgres (+ Redis/Celery recommended)
- **Local dev:** `runserver` on laptop; public URL needs VM
- **Admin:** browser → `https://domain/admin/` hosted on the VM

### Exchange 9 — Postgres UI and Caddy

**User:**

> Então postgres não tem ui igual o sqlserver?
> caddy é alternativa para nginx?

**Assistant:**

- **Postgres** has no bundled GUI (like SQL Server without SSMS). Use **pgAdmin**, DBeaver, or terminal `psql`. **Django Admin** is application UI, not database UI.
- **Caddy** and **Nginx** are equivalent reverse proxies; Caddy has simpler automatic HTTPS (used in Pilot 01 for Label Studio).

### Exchange 10 — Kobo submission simulation

**User:**

> Simulei chega submissão Kobo → o que acontece em cada segundo") na vm

**Assistant:**

Step-by-step timeline:

1. **0–8 s:** Volunteer submits; Kobo stores; VM unaware
2. **~5 min:** Celery beat triggers `poll_kobo_submissions`
3. **0.3 s:** Worker fetches new submission from Kobo API
4. **0.5–8 s:** Download photos; P0 validation (Pillow, EXIF strip, SHA-256)
5. **8–10 s:** `boto3 put_object` to Hetzner bucket
6. **10–11 s:** INSERT `Image` + `Event` in Postgres
7. **11–15 s:** Optional Label Studio task creation

Also described webhook variant (Django 200 OK → Celery processes). Noted Gunicorn/Caddy not involved in poll path.

### Exchange 11 — pgAdmin on VM?

**User:**

> Vou precisar de pgadmin tambem na vm?

**Assistant:**

**No.** Postgres runs without pgAdmin. Django Admin suffices for operations. pgAdmin optional for developers — preferably on laptop via SSH tunnel, not exposed publicly.

### Exchange 12 — Bucket confirmation

**User:**

> Depois de gravar a imagem no bucket, o bucket confirma se foi salva avisa o Django? Ou o próprio django vai precisar fazer algum check?

**Assistant:**

**Bucket does not notify Django.** Confirmation is **synchronous** in `put_object` HTTP 200 response (+ `ETag`). Flow: validate → upload → if OK → Postgres `Image` row. No bucket webhook needed for pilot. Optional `head_object` double-check.
